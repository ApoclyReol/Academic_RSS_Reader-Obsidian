# Academic RSS Reader

[English](README.md) | 简体中文

> **把分散的学术 RSS 订阅，整理成一个可以持续筛选、翻译和排序的本地阅读队列。**

Academic RSS Reader 是一款面向学术文献初筛的 Obsidian 桌面插件。它把 RSS/Atom 订阅汇总到本地 SQLite 数据库，用五个清晰的文献篮子保存你的阅读判断，并根据这些判断为未读文献排序。不需要 Python sidecar。

它关注的是“新文献到达”与“知道哪些值得进一步阅读”之间的初筛环节：减少重复整理，让你更快回到真正值得投入时间的文献上，而不是替代文献管理器或全文数据库。

> [!IMPORTANT]
> 当前推荐版本：**1.6.1**。本版本要求 Obsidian **1.13.0 或更高版本**，仅支持桌面端；实际运行还需要 Obsidian 内置的 Node.js **22.16 或更高版本**提供 `node:sqlite` 的 `DatabaseSync` 和 SQLite Backup API。安装或更新前，建议先升级到最新可用的 Obsidian 桌面版。

## 为什么使用 Academic RSS Reader

- **统一阅读队列**：把期刊、出版社、实验室和其他 RSS/Atom 订阅放到一个阅读器里。
- **根据你的判断排序**：将文献标记为感兴趣、归档、隐藏或过期后，用这些真实的阅读决策为未读队列排序。
- **流程足够简单**：收集、浏览、分类，再回到真正值得精读的文献。
- **本地优先**：订阅、文献、阅读状态、翻译、推荐和分析数据保存在你指定的 Vault 目录内。
- **按需辅助**：可以翻译当前可见的标题，也可以让你配置的 OpenAI 兼容服务只复核仍处于待判断状态的文献。
- **可恢复、可解释**：数据库迁移前自动创建保护备份；推荐结果保留正向和负向关键词证据，并把订阅默认期刊与 RSS 文章提供的期刊信息分开管理。

核心原则很简单：插件负责重复性的收集和整理，最终判断始终交给你。

## 它是怎么工作的

```text
选择 Vault 内的数据目录
        ↓
添加或导入 RSS/Atom 订阅
        ↓
更新订阅并收集新文献
        ↓
浏览未读篮子并标记阅读状态
        ↓
更新本地个性化推荐
        ↓
按需用 LLM 复核待判断文献
```

## 适合哪些人

如果你符合下面几项，Academic RSS Reader 会比较适合你：

- 通过 RSS 关注多个期刊、出版社、实验室或研究主题；
- 新文献数量经常超过你当下能够阅读的数量；
- 希望阅读队列体现自己的判断，而不是依赖通用热度排序；
- 希望把研究资料保存在本地 Obsidian Vault 中；
- 想要轻量的标题翻译，但不希望每篇文献都发送给 AI 服务。

## 它能做什么

### 收集和管理订阅

- 添加、编辑、启用、停用和删除订阅。
- 导入 OPML、XML、TXT、粘贴的订阅列表，或逐行输入 URL。
- 每次启动后首次打开阅读器时自动更新启用订阅；一小时内成功更新过的订阅会自动跳过并显示数量，手动更新始终强制执行。
- 使用 ETag、Last-Modified、HTTP 304、有界并发、重试等待、超时、取消、健康状态和自动退避，减少重复更新带来的噪声。
- 从订阅中提取标题、作者、来源、年份、DOI、链接，以及源站提供的摘要。
- 保持稳定身份、标题规范化、跨订阅关联、已有阅读状态，并进行分层重复检查。

### 用五个文献篮子完成初筛

- 使用 **未读**、**感兴趣**、**归档**、**隐藏**、**过期**五个篮子管理文献。
- 长列表按每批 100 条连续加载，不一次性渲染整个数据库。
- 可分别控制卡片是否显示期刊、作者、发表日期、DOI、订阅源文本摘要和摘要图；标题、相关度和操作始终保留。
- 在系统浏览器中打开原文。
- 在当前阅读器会话中撤回最近一次状态操作。

### 为未读队列排序

- 使用 TypeScript TF-IDF 和逻辑回归模型在本地训练推荐结果。
- 将感兴趣和归档文献作为正样本，将隐藏和过期文献作为负样本。
- 显示高相关、待判断和低相关层级，并在固定高度的三行标题下用紧凑的状态框和两行关键词展示最有影响的正向、负向证据。
- 训练和正式评分使用同一套 TF-IDF 特征尺度；取消后台训练不会写入过期结果。
- 在关键词词表中逐词停用或重新启用，逐步减少不符合你习惯的词。
- 每批订阅更新后自动刷新推荐；训练数据没有变化时复用已有模型，并尽量只计算新增或内容变化的未读文献。
- 可选地使用你配置的 OpenAI 兼容 LLM 复核待判断文献；正常更新订阅时不会自动调用 LLM。

本地推荐模型至少需要 2 篇正样本和 2 篇负样本。在反馈不足时，文献可以保持未评分，不会被强行赋予一个看似精确的个性化判断。

### 翻译和兴趣分析

- 翻译当前可见的文献标题，并在滚动时预取后续 8 个标题。
- 将译文缓存在本地数据库，随时可以切回原标题。
- 查看总体阅读状态，并比较不同订阅的感兴趣率。
- 界面语言跟随 Obsidian，内容翻译目标语言单独设置，互不影响；原始语言会自动识别，适合混合语言订阅。
- 目标语言支持简体中文（`zh-CN`）、繁体中文（`zh-TW`）、英语（`en`）、日语（`ja`）、韩语（`ko`）、法语（`fr`）、德语（`de`）、西班牙语（`es`）、葡萄牙语（`pt`）、意大利语（`it`）和俄语（`ru`）；设置选项会显示对应代码，便于确认实际目标。

### 数据模型与安全边界

- 启用期刊显示时，每张卡片只显示一个期刊名：优先使用随 RSS 更新的文章级期刊名，仅在缺失时回退到最早关联订阅的默认期刊名。
- 卡片设置默认保持 v1.5.0 外观：显示期刊和摘要图，隐藏作者、发表日期、DOI 和文本摘要。
- 所有卡片根据全局启用的行槽使用统一高度：标题预留三行、作者一行、文本摘要三行；单篇文献字段缺失或图片加载状态不会改变卡片高度。
- 关闭摘要图后不会创建卡片图片元素，也不会发起对应远程请求；启用时仍采用懒加载和失败隐藏。
- 标题中的 `$...$`、`$$...$$`、`\(...\)` 和 `\[...\]` 片段使用 Obsidian 原生 MathJax 渲染；无效公式回退为原始文本。
- 文章链接只允许 `http:` / `https:`；RSS/XML 拒绝 `DOCTYPE`、无效根结构和超过 10 MiB 的响应，并只移除已知跟踪参数，保留业务参数。
- LLM 仅允许 HTTPS，或 `localhost`、`127.0.0.1`、`::1` 的本机 HTTP；请求有 30 秒超时和有限重试。

## 开始使用

1. 打开“设置 → 第三方插件 → 浏览”，搜索 **Academic RSS Reader**，安装并启用插件。
2. 打开“设置 → Academic RSS Reader”，在当前 Vault 内选择一个数据目录。
3. 新安装选择“创建新数据库”；已有 `rss-reader.sqlite3` 时选择“载入数据库”。v1.3 及更早数据库会在载入时原地升级，升级前自动写入保护备份；迁移失败会恢复原库。
4. 点击 RSS 功能区图标打开阅读器，或按 `Cmd/Ctrl + P` 搜索并运行“打开阅读器”。
5. 添加订阅或导入 OPML/订阅列表，然后执行更新。
6. 按照自己的阅读判断标记文献。积累足够样本后，在“个性化推荐”中点击“更新关键词推荐”。
7. 如果需要额外复核，在设置中配置 OpenAI 兼容服务地址、模型和 SecretStorage API Key，再主动执行“LLM 复核待判断”。

如果社区插件目录不可用，只从对应的 GitHub Release 下载 `main.js`、`manifest.json` 和 `styles.css`，放入：

```text
<Vault>/.obsidian/plugins/academic-rss-reader/
├── main.js
├── manifest.json
└── styles.css
```

不要安装 GitHub 自动生成的源码压缩包。从旧插件 ID `rss-reader` 手动升级时，先关闭 Obsidian，将旧插件目录重命名为 `academic-rss-reader`，再替换这三个发布文件，并保留 `data.json`，这样首次加载时才能把旧 LLM Key 迁移到 SecretStorage。

## 数据与隐私

运行数据库保存在你选择的 Vault 相对目录中：

```text
<Vault>/<用户选择的数据目录>/
├── rss-reader.sqlite3
└── backups/
```

订阅、文献、阅读状态、译文、推荐和兴趣分析保存在本地 SQLite。普通设置保存在插件目录的 `data.json`；LLM API Key 由 Obsidian SecretStorage 保存，`data.json` 只记录所选 SecretStorage 条目的名称。

Academic RSS Reader 不要求注册账户，不运行遥测，也没有开发者中转服务器。网络请求只发往你实际使用的服务：

- RSS/Atom 更新请求发送到你配置的订阅 URL。
- 标题翻译使用 Google 非正式网页接口。启用后，当前可见和预取的标题会由本机直接发送；接口可能限流或失效，译文也可能不准确，不应作为正式引用。请求会超时并按退避策略有限重试；连续失败后停止自动请求，失败任务可在网络恢复后手动重试。
- 只有在你主动测试连接或复核待判断文献时才会发起 LLM 请求。请求会包含复核所需的文献信息和你填写的研究兴趣描述，并发送到你配置的服务地址。

插件不会在启动时创建或打开数据库。只有在你选择 Vault 内的数据目录并明确执行创建或载入后，才会开始数据库操作。数据库保存使用经过校验的临时文件和上一版本保护文件；设置页可以手动创建保护备份，并恢复最近的有效备份。数据库主文件、WAL/SHM sidecar、临时文件和备份由桌面原生 SQLite 能力处理，其他 Vault 文件仍受 Obsidian `DataAdapter` 边界保护。

## 兼容性与边界

- 仅支持桌面版 Obsidian：macOS、Windows 和 Linux 桌面安装。
- 要求 Obsidian 1.13.0 或更高版本，以及内置 Node.js 22.16+ 的 `node:sqlite` 能力；不满足时会阻止载入数据库并提示更新 Obsidian，不提供 `sql.js` fallback。
- 不需要 Python、单独安装的 Node.js 或 sidecar 进程。该运行时要求由 Obsidian 桌面版提供。
- 标题翻译是辅助阅读功能，不是正式翻译或引用服务。
- 数据库面向单个本地桌面 Obsidian 实例使用，不是多人共享数据库，也不建议多个进程同时写入同一个文件。
