# 旧版数据迁移

## 准备

1. 保留旧 Streamlit 项目和 `data/rss_reader.sqlite3`。
2. 关闭旧软件，确保数据库没有正在写入。
3. 备份旧数据库。
4. 在独立测试 Vault 中安装 RSS Reader v1.0.0。

## 导入

1. 打开“设置 → RSS Reader → 旧数据迁移”。
2. 选择旧版 `rss_reader.sqlite3`。
3. 先执行只读预览，核对 schema 和各表数量。
4. 点击“确认导入”。
5. 在阅读、订阅管理和兴趣分析中核对结果。

导入前插件会保存：

- 旧数据库副本
- 当前插件数据库恢复点
- 不包含摘要全文和密钥的 JSON 报告

## 兼容行为

- 永不修改或删除旧数据库。
- 核心导入在单个事务中完成，校验失败时回滚。
- 按订阅 URL 和旧版 stable GUID 保持幂等。
- 条目、订阅和关联主键会安全重映射。
- 用户篮子状态、推荐分数、关键词和模型随数据导入。
- API Key 不自动导入。
- 历史条目不会自动发起翻译。

v1.0.0 沿用旧 Streamlit 的 GUID 和标题规范化规则。预发布 Obsidian 版本曾错误使用动态 CNKI 链接生成 GUID；v1.0.0 启动维护只合并这些非旧版格式记录，不改写正常历史 GUID。

## 验收

至少检查：

- `PRAGMA integrity_check` 返回 `ok`
- `PRAGMA foreign_key_check` 无结果
- `items` 与 `item_feeds` 数量及关联合理
- 旧 GUID 无缺失
- 五类状态数量与旧库一致
- 重复执行导入不会增加条目

项目开发阶段用于回归的旧库基线曾包含 34 个订阅、1,629 个条目和 1,629 条关联；实际迁移必须以用户现场预览为准，不能把该数量作为强制条件。
