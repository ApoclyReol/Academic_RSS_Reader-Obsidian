# Obsidian 插件迁移计划

## 目标

将旧版 Python/Streamlit RSS Reader 迁移为 Obsidian 原生阅读工作流，同时保留现有数据和核心行为。

本目录是新的插件实现边界；旧项目继续作为迁移期的行为基线和数据来源，不在本阶段修改或删除。

## 保留的产品语义

- 阅读入口位于文献阅读工作流，而不是恢复独立的筛选页。
- 条目区分未读、已读、收藏与隐藏状态。
- 批量筛选默认执行“隐藏”，不永久删除条目，并提供恢复入口。
- 个性化推荐保留高相关、待判断、低相关分层及人工调整能力。
- Vault 内的 Markdown 笔记是可读、可迁移的用户资产。

## 建议技术边界

| 层级 | 职责 | 首选实现 |
| --- | --- | --- |
| Obsidian UI | 阅读列表、详情、订阅管理、设置 | ItemView、Modal、Setting |
| Application | 刷新订阅、更新阅读状态、推荐、收藏 | TypeScript services |
| Domain | Feed、Entry、ReadingState、Recommendation | 纯 TypeScript 类型 |
| Persistence | 结构化索引和插件设置 | Adapter API 下的插件数据目录 |
| Knowledge | 收藏或归档内容 | Vault Markdown |

不要把大量条目索引全部塞进 `data.json`；`data.json` 只保存小型设置。正式确定存储方案前，应先测量旧数据库规模，并设计可校验、可回滚的数据导入流程。

## 分阶段交付

### 0. 基础框架

- 可构建、可加载的插件
- 阅读器视图、命令和设置页
- 代码边界与迁移文档

### 1. 订阅与阅读

- Feed CRUD 与 OPML 导入/导出
- RSS/Atom 抓取、解析、去重
- 未读列表、详情、已读/收藏/隐藏状态

### 2. Vault 集成

- 收藏条目生成 Markdown
- 模板与目标目录设置
- 双向定位来源条目和笔记

### 3. 个性化推荐

- 迁移关键词、反馈与评分模型
- 高相关/待判断/低相关分层
- 隐藏操作的撤销和恢复

### 4. 旧数据导入与发布

- 只读扫描旧数据库并生成迁移预览
- 迁移前备份、数量校验、幂等导入与回滚
- 独立测试 Vault 验收
- 发布包和安装文档

## 下一阶段开始前需确认

1. 旧版 SQLite 的实际 schema、数据量和附件边界。
2. 是否要求移动端可用；这会影响存储和网络请求方案。
3. RSS 正文的缓存策略、保留周期和空间上限。
4. 推荐模型是完全迁入 TypeScript，还是保留可选本地 sidecar。
